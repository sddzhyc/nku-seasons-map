# 植物位置描述维护

地图弹窗的“大致位置”来自附近的校内 OSM 地标，例如“秀山堂附近，日新道沿线”。它用于帮助辨认大致区域，不是门牌地址、步行导航或入口指引。

## 人工修改

编辑 `data/locations.yaml`，以完整 OSM 要素编号填写 `overrides`。编号可从开发模式弹窗的“查看 OSM 原始要素”链接获得；也可搜索生成的 `public/data/locations.json` 中的 `entries`。点、道路/树林、多多边形分别以 `node/`、`way/`、`relation/` 开头。

```yaml
schema_version: 1
overrides:
  way/1448582302:
    text: "秀山堂附近，日新道沿线" # 请按现场情况修改
    note: "修改依据或现场核对日期，供维护者查阅" # 可选，不在普通弹窗展示
```

`text` 为 1—180 字，`note` 最多 500 字。配置文件和生成文件都在公开仓库中，不应填写私人信息。

人工条目优先于自动描述，OSM 同步、浏览器实时更新和重新构建都不会改写 `data/locations.yaml`。删除某个条目即可恢复自动推断。没有人工条目的新增植物会自动生成位置；OSM 将要素拆分、合并或更换编号时，旧条目保留在配置中，并列入 `locations.json` 的 `unusedOverrideIds`，需维护者确认后迁移，系统不会猜测新旧对应关系。

开发服务会监听这个文件，保存后校验、重新生成数据并刷新页面。正式发布时提交 YAML，让 Actions 重建并部署即可。手动本地构建使用 `npm run data:build`；不要直接编辑 `public/data/locations.json`，它会被覆盖。

## 自动描述如何生成

- 从校园及周边简图挑选与实际校界相交的具名建筑、校内道路、湖泊、花园、广场及入口；跳过校外参照、店铺、公交站和单独的“A区”等模糊名称。
- 在植物实际几何上选取代表点，用建筑轮廓和道路几何计算距离，而不是比较地图标注或建筑中心点。建筑/景观点不超过约 200 米，道路不超过约 90 米，才用于“附近／沿线”描述。近距离排序对建筑略有优先。
- 多片树林分别取代表点，合并重复描述，最多展示三处并用“等”说明还有其他分布。长树列与树林的文字是概略参照，实际范围以地图轮廓为准。
- 附近没有合适地标时只提示校园方位及资料不足，不引用远处的建筑冒充邻近地点。自动文字会随发布的地标数据更新；浏览器实时获取新的植物几何时也会重新推断，人工覆盖仍优先。

后台输出 `locations.json`（人工配置、参照地标、每处植物的文字、来源及距离依据），并将同一份信息放入原子数据包 `site-data.json`，页面不需要另行访问地址解析服务。位置配置、地标和自动文字都参与发布版本计算，改字也会触发浏览器的数据更新。

几何处理使用 Turf 的 [pointOnFeature](https://turfjs.org/docs/api/pointOnFeature)、[pointToPolygonDistance](https://turfjs.org/docs/api/pointToPolygonDistance) 等计算；位置文本始终按纯文本显示。
