# 当前技术设计

## 调研与选型

参考 [樱花花期地图](https://rogerzhu.github.io/yinghua-map/) 的公开页面和 [源码](https://github.com/rogerzhu/yinghua-map)，确认其采用 Leaflet、浅色底图、日期计算及阶段过滤。借鉴地图与日期列表的联动，独立实现本项目的真实 OSM 点、树列及多多边形。参考 [OpenTreeMap](https://opentreemap.github.io/) 按物种组织树木记录的方式，保留查询和来源追溯，省去当前不需要的账户/复杂管理系统。

| 部分           | 方案                              | 目的                                                     |
| -------------- | --------------------------------- | -------------------------------------------------------- |
| 前端           | TypeScript、Vite、Leaflet、Lucide | 校园规模下轻量交互、点线面统一渲染、静态构建             |
| OSM 查询       | Overpass + osmtogeojson + Turf    | 按校园范围提取并保留实际几何，合并关系成员，筛选相交对象 |
| 开发者数据库   | `data/phenology.yaml`             | 可直接编辑、版本化和审查的年度物候资料                   |
| 数据后端       | Node.js TypeScript 脚本           | 统计物种索引，校验与编译 YAML，更新最后有效快照          |
| 前端物候计算   | 共享 `src/phenology.ts`           | 上海时区、年度区间、资料过滤、物种别名与阶段匹配         |
| 数据发布       | 一个 `site-data.json` 原子包      | 防止不同版本的物候、索引和 OSM 数据混读                  |
| 持续更新与托管 | GitHub Actions、GitHub Pages      | 每6小时同步、检查、回存有效快照并部署                    |

[Leaflet 官方文档](https://leafletjs.com/examples/geojson/) 支持按 GeoJSON 属性设置样式。[GitHub Pages 是静态托管](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)，因此本项目把后端维护/统计放在 Node 与 Actions 中。无需常驻数据库服务；以后若加入身份认证编辑后台或秒级推送，再独立提供 API。

## 数据与交互

```text
OSM / Overpass → 几何完整性校验 → 校园相交筛选 → 植物及校园快照
                                                        ↓
YAML → 来源/日期/重叠/别名校验 → 物候库 + 后台物种索引 → 一体数据包
                                                        ↓
                         浏览器 → 日期/类别/阶段/资料筛选 → 地图高亮
```

分布与物候模式共享同一个 GeoJSON 高亮入口。分布模式颜色代表物种；物候模式颜色和虚线代表阶段。一个要素有多个物种时，只要存在符合条件的记录就展示；若同时匹配多阶段，显示所选类别中较后的阶段，单物种筛选则只取该物种的匹配结果。弹窗仍逐项列出物种资料，避免颜色覆盖后丢失信息。

新物种不必等到 YAML 填好才出现在地图上：后端将其索引中的 `phenologyId` 记为 null，前端分布模式继续展示，物候模式仅列出已登记所选类别日期的物种，缺失日期的物种仍可在分布模式查找。

## 更新层次

校园简图单独查询校界周边的 OSM 背景要素，并将返回的长道路、大面积用地裁剪到固定邻域范围。后台以真实校界生成 180、360、600、900 米外扩环带；前端在底图上叠加逐层加深的背景色蒙层，校内不覆盖。这样同一条道路穿过校界时，校内清晰、校外逐步变浅，不会因按整条道路分类而丢失距离差异。地名使用相同环带降低对比度，植物图层仍按校园相交筛选。缺少校外背景的响应会被拒绝，保留已有有效简图。

外扩及几何运算仅在数据脚本中执行，不增加前端几何依赖；产物包含来源、范围、获取时间及淡化区间，支持静态部署。

- 浏览器每15分钟检查站点数据包和在线 OSM 图层；较新的浏览器 OSM 缓存不会被旧发布快照覆盖，物候库则跟随站点新版本。
- Actions 每6小时完整查询一次校园数据，校验后生成简图、索引和数据包。只有测试和构建成功后才将快照回存 Git。
- 查询异常时保留旧数据，更新时间不改成当前时间。YAML 错误不能通过网络失败降级绕过。
- OSM 编辑提交、Overpass 复制、网站查询和标准瓦片重绘分别存在延迟，不构成秒级推送承诺。

## 实现边界

六项功能均有代码实现：点线面高亮、后台统计查询列表、YAML 年度多区间、当日状态筛选、在线刷新、Actions/Pages 工作流。当前资料只为银杏秋叶和山桃花期填入待校准区间，其他条目保留空日期；没有现场观测服务。远程发布需要关联目标仓库并启用 Pages，具体状态以实际工作流结果为准。
